# 06 - 文字渲染端到端自动测试方案（免人工开游戏核对）

> 状态：设计完成，待评审后实施
> 依赖：docs/05 v2 的缺陷清单（N1-N15）与四步整改方案
> 目标：**提交序列 → 帧截图 → 断言**，全流程无人工。跑一次 < 60 秒（本地 PC），真机可选。

---

## 1. 核心思路

docs/05 已经证明：bug 全部发生在「**提交序列 → 回放渲染**」这条链上，且与**同帧提交顺序**强相关（N1 的 style 切换、2.1 的 scale 竞态）。因此端到端测试的最小充分单元不是"游戏画面"，而是：

1. **受控的提交序列**：直接驱动 `CFont::SetScale/SetFontStyle/PrintString`，精确复刻 bug 触发时序（中西交替、scale 梯度、style 切换、图标 token 混排）；
2. **回放后的帧缓冲读取**：`RenderFontBuffer()` 把 quad 写进 `CSprite2d` 顶点缓冲并渲染，一帧结束后从 GL 读回像素；
3. **断言**：
   - **几何断言**（不依赖渲染）：拦截 `CSprite2d::AddToBuffer`，记录每个文本 quad 的 `(x, y, w, h, uv)`——比像素更稳、可直接检查 docs/05 §8.5 的核心不变量；
   - **像素断言**（依赖渲染）：区块内非背景像素占比、行间距的投影分布——捕捉"变细/乱码/双图标"这类视觉效果。

两条腿互补：几何断言抓根因（advance 一致性、UV 合法性、段头不被当字形），像素断言兜底（渲染路径的最终真相）。

## 2. 测试钩子设计（C++ 侧，一个新文件 `src/tests/FontHarness.cpp`）

### 2.1 触发方式：环境变量 `REVC_FONT_TEST=<script.json>`

不动命令行解析，仿照 `REVC_HUD`（perfhud.cpp:33 的 `getenv` 先例）。游戏正常启动到菜单后，`FrontendIdle()` 的 `DoRWStuffEndOfFrame()` 前检测到该变量即进入测试循环（不进游戏，省去 loading）。

### 2.2 测试脚本格式（JSON，声明式提交序列）

```json
{
  "name": "T_N1_style_switch_cjk_then_ascii",
  "frames": [
    {
      "submits": [
        {"op": "style", "style": "FONT_JAPANESE"},
        {"op": "scale", "x": 1.5, "y": 1.5},
        {"op": "shadow", "pos": 2},
        {"op": "print", "x": 320, "y": 100, "text": "中文标签"},
        {"op": "style", "style": "FONT_HEADING"},
        {"op": "scale", "x": 0.9, "y": 0.9},
        {"op": "print", "x": 320, "y": 200, "text": "12:34"}
      ],
      "grab": "frame_001"
    }
  ],
  "asserts": [
    {"type": "quad_count", "grab": "frame_001", "expect": 6},
    {"type": "uv_in_atlas", "grab": "frame_001"},
    {"type": "advance_match_measure", "grab": "frame_001"},
    {"type": "glyph_spacing", "grab": "frame_001", "y_band": [90, 140],
     "expect_width": [21, 26], "tolerance": 2}
  ]
}
```

text 字段支持：`\u7801` 转义、`{ICON:T}`（展开为 `~T~`）、`{JTOKEN:h}`（展开为带 0x8000 标志的 `~h~`，复现 CJK GXT 的真实字节）。

### 2.3 拦截层：`REVC_FONT_HARNESS` 编译开关下的 AddToBuffer 记录

在 `CSprite2d::AddToBuffer` 入口加：

```cpp
#ifdef REVC_FONT_HARNESS
void FontHarness_RecordQuad(const CRect&, const CRGBA&, const RwV2D* uvs);
#endif
```

记录到固定数组（上限 4096 quad），随 `RenderFontBuffer()` 开头的 `Sprite[...].SetRenderState()` 之前清空——即**每次 flush 一个批次**，天然按"段批次"分组，正好对应 docs/05 的分析单元。

**注意**：perf HUD 的 `Hud_Draw()` 在 `FrontendIdle` 里也走 CFont，测试模式下跳过它（`gPerfHudEnabled` 强制 0），菜单绘制期间进入测试循环前先 `RenderMenus()` 一次让菜单自身 flush 完，避免串扰。

### 2.4 像素抓取：复用 `RwGrabScreen`（main.cpp:337）

已存在且好使（写 PNG 到根目录）。测试模式下改名 `grab_<script>_<frame>.png` 输出到 `test-out/`。librw 构建有 `RtPNGImageWrite`（`#ifdef LIBRW` 分支）——本地与 Docker 都是 LIBRW 路径，无需新代码。

### 2.5 帧推进与退出

测试循环在 `FrontendIdle` 末尾接管：执行完脚本所有 frames 后写 `RESULT.json`（含每条 assert 的 pass/fail 与实测值），然后 `RsGlobal.quit = TRUE` 退出。**退出码**：main 返回 0/1，shell 一眼判定。

## 3. 断言库（对应 docs/05 缺陷 → 测试映射）

| 断言 | 检查内容 | 抓的缺陷 |
|---|---|---|
| `quad_count` | flush 批次内文本 quad 数 == 预期 | N1（整段消失→计数骤减）、偶数串消失（e20c6858 回归） |
| `uv_in_atlas` | 每个 quad 的 UV 落在图集网格内（u∈[0,1], v∈[0,1]，CJK 还要落在 64 列网格线上） | N1 反向（数字 UV 被改成 CJK 网格→乱码）、B3（闭合符当字形→yoff=513） |
| `advance_match_measure` | **核心不变量**：`GetStringWidth(s)` == 该段回放 advance 累加和 | N2/N11/N14（测量与回放两套宽度规则） |
| `glyph_spacing` | 同一 y 行内相邻 quad 左边距差 ∈ [CJK_ADVANCE·min_scale, CJK_ADVANCE·max_scale] | A1（变细=字窄距宽）、N3（行距重叠用 y 投影测） |
| `shadow_present` | 每个主 quad 存在偏移 (shadowPos, shadowPos) 的对应深色 quad | A1（阴影消失） |
| `icon_count` | `DrawButton` 调用次数（harness 拦截记录）== 1 | B2（两个 Y）、B1 |
| `icon_gap` | 图标 quad 后第一个文本 quad 的 x - (图标 x + 17·scaleY) < 阈值 | B3（图标后空格） |
| `pixel_ink_ratio` | 给定矩形区域内非背景像素占比 ∈ [lo, hi] | 兜底：变细/发虚/乱码 |
| `no_crash` | 脚本跑完进程退出码 0 | hang 回归（92bcace3 前的那次） |

`advance_match_measure` 的实现要点：harness 在提交每个 `print` op 时同时调用 `GetStringWidth`（提交语义，读 Details）记录测量值；回放拦截里按 `RenderState.scaleX * GetCharacterWidth` 逐字累加记录实际值；帧结束比对。这正是 docs/05 §8.5 点名的那条不变量。

## 4. 测试用例清单（首批 12 个，直接映射缺陷表）

| 用例 | 提交序列要点 | 断言 | 对应缺陷 |
|---|---|---|---|
| T01 偶数中文串 | 单段 `选项` | quad_count=2, 居中 | e20c6858 回归 |
| T02 中西交替同帧 | 中文段(style3)→ASCII段(style1) | quad_count、uv_in_atlas | **N1** |
| T03 西中交替同帧 | ASCII 段先、中文段后 | uv_in_atlas（数字不得走 CJK 网格） | **N1 反向** |
| T04 scale 梯度 | 同 style，scale 1.5→0.9 两段 | glyph_spacing 各段各自一致 | A1/GDB 2.1 |
| T05 阴影稳定性 | CJK 带 shadow=2，同帧后续段无 shadow | shadow_present | A1 |
| T06 图标单次 | `{JTOKEN:h} {ICON:T} {JTOKEN:w} 按` | icon_count=1, icon_gap | **B1/B2/B3** |
| T07 段尾 token | token 位于串末尾 | quad_count 不多不少、无越界 UV | **N7** |
| T08 颜色 token | `{JTOKEN:r}红字` | pixel_ink_ratio（颜色生效→非灰色） | N8 |
| T09 prop-off 数字 | SetPropOff + `12:34` | advance_match_measure | **N2/N11** |
| T10 换行行高 | 超长中文串 wrap | y 投影行距 ≥ 字高 | **N3** |
| T11 超长单词 | 无空格超行宽 CJK 串 | no_crash + 行数正确 | N4/N5、hang 回归 |
| T12 测量=回放 | 混合全部元素 | advance_match_measure | 全家族回归闸 |

## 5. runner（Python，`tools/l10n/test/test_font_e2e.py`，与 test_gxt.py 同级）

```
用法: python3 tools/l10n/test/test_font_e2e.py [--bin path] [--cases dir]
1. 扫 cases/*.json
2. 对每个: REVC_FONT_TEST=<abs> ./reVC 跑（cwd=/tmp/vc-local/game，复用现有游戏资源）
3. 读 test-out/RESULT.json → 汇总 pass/fail 表格（含实测 vs 预期）
4. 保留失败帧的 grab PNG 供人眼看（可选 --review 起一个简单 HTTP 列表）
5. 退出码：全绿 0
```

CI/本地一条命令：`cmake --build build-local -DREVC_FONT_HARNESS=ON` 后跑 runner。**真机**亦可跑同一脚本（ssh + REVC_FONT_TEST 环境变量），验收时顺带当回归闸。

## 6. 边界与风险

- **harness 记录必须编译期可关**（`REVC_FONT_HARNESS` 默认 OFF），零开销发布版。
- `FrontendIdle` 接管点选在 `RenderMenus()` 之后、`DoRWStuffEndOfFrame()` 之前——菜单自身已 flush，测试提交序列从干净状态开始。
- 游戏资源依赖：复用 `/tmp/vc-local/game`（ANIM/AUDIO 已补全）。runner 里加资源存在性预检，缺失即 skip 并提示。
- 像素断言对 Mesa/真机 Mali 的 AA 差异敏感 → 阈值放宽，几何断言为主、像素为辅。
- `RESULT.json` 写在游戏根目录（CFileMgr 根），runner 用 `--out` 传绝对路径（通过 env `REVC_FONT_TEST_OUT` 传入）。

## 7. 实施顺序（半天~一天）

1. `FontHarness.cpp/.h` + CMake `REVC_FONT_HARNESS` 开关 + AddToBuffer/DrawButton 拦截（~150 行）
2. JSON 解析 + 提交驱动 + RESULT 写出（~200 行，用现成的 json——**不引第三方**，游戏里已有简单的手写解析可抄 `MenuScreensCustom` 的 CFO 段，或直接用极简 `key:value` 行格式替代 JSON，进一步降依赖）
3. runner 脚本（~100 行）
4. 首批 12 用例 JSON（~100 行）
5. 接入 docs/04 的 T1-T5 之后作为 T6+（编号顺延）

> 备注：如果不想在 C++ 里做 JSON，2 可以退化为**命令行脚本格式**（每行一个 op，`#` 注释），解析 30 行搞定。渲染端值不值得做 JSON 由实现时定，此文档两种都许可。
